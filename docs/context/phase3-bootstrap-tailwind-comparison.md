# Fase 3 — Aurum UI, Bootstrap e Tailwind no layout

Estado em 07/11/2026: **comparativo verificado e princípio de uso aprovado pelo analista; nenhuma classe, diretiva ou componente Harpia de layout foi implementado**. Esta nota aprofunda a [auditoria inicial](audit-aurum.md) para a [fase 3](implementation-plan.md). A fonte Aurum UI é a versão 1.0.18; Aurum-Smart é sua vitrine. Bootstrap 5.3 e a documentação atual do Tailwind CSS são referências de ergonomia, sem compromisso de copiar suas APIs ou valores.

## Comparação por cenário

| Cenário | Aurum UI 1.0.18, verificado no código | Bootstrap 5.3, documentação oficial | Tailwind CSS, documentação oficial | Direção Harpia aprovada ou ainda aberta |
| --- | --- | --- | --- | --- |

| Formulário e agrupamento | `FormRow` encapsula `Row`; `FormControl` mistura posição de coluna com label/hint/erro. `FormGroup` cria `fieldset`/`legend` e pode desabilitar o conjunto. | O layout usa grid e utilitários em HTML nativo; o Bootstrap 5 retirou classes específicas `.form-row`/`.form-group` em favor de grid/utilitários ([migração](https://getbootstrap.com/docs/5.3/migration/), [forms layout](https://getbootstrap.com/docs/5.3/forms/layout/)). | Utilitários e variantes atuam em `form`, `fieldset`, `legend`, `label` e `input` existentes ([estados](https://tailwindcss.com/docs/hover-focus-and-other-states)). | Preservar semântica nativa de `fieldset`/`legend`; separar layout da validação do campo. ## Princípio de implementação orgânica

**Decisão do analista nesta etapa:** o consumidor deve poder usar os elementos HTML adequados à semântica do conteúdo e aplicar o layout por classes/estilos do Harpia, sem precisar instanciar um componente como `AurumGrid` nem adicionar uma diretiva de layout. A mesma orientação vale para linha, colunas, seção e agrupamento visual simples. Uma diretiva ou componente futuro exige comportamento que CSS e HTML nativo não cubram de modo suficiente, com justificativa e aprovação próprias. Para formulários, a estrutura nativa `form`/`fieldset`/`legend` continua essencial; classe visual não deve substituí-la.

Isto define **forma de consumo**, não a lista ou grafia de classes, nem o número de colunas, os breakpoints ou a estratégia de geração. Bootstrap e Tailwind demonstram dois modelos de classes com amplitudes diferentes. A inferência para Harpia é iniciar com o menor conjunto que cubra os cenários aprovados e medir ergonomia, CSS gerado e conflitos antes de ampliá-lo.
